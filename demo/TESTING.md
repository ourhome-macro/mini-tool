# 墨阅 · 故障注入与边界测试记录

日期：2026-10-23  
浏览器：Microsoft Edge 155.0.4283.62（headless）  
视口：1440 × 1000、390 × 844  
服务：`python -m http.server 8899`，同时验证过 `file://` 直接打开

## 结论先放这里

- **可以连续打开多个 Markdown。** 文件选择支持多选，也可以一次拖入多份；它们都会进入左侧「本地书架」，在同一个页面里切换。测试到 **44 份文档**，切换、刷新恢复都正常。
- 3 个实际文件通过文件选择器一次打开；另有 2 份、30 份文件通过拖拽打开，均已通过。
- 同名同内容文件会去重；同名但内容不同的文件会并存，书名相同时侧栏用文件名区分。
- 发现并修复了 5 个值得修的问题：超大文档搜索漏项、二进制文件被当文本、病态深层列表撑破卡片、同名文档难区分、多选能力不可见。
- 优先级最高的提升方向：本地存储容量、超大文档搜索的同步阻塞、按文档记住阅读位置。

## 修复记录

1. **搜索漏掉文档后半段**  
   原先搜索索引最多收录 900 个块，500 标题 + 500 段落的文档搜不到最后一节。已移除硬上限，并按块建立完整索引；搜索结果仍限制前 40 条。

2. **二进制 `.md` 被当作文本打开**  
   原实现直接 `File.text()`，会把 `0x00` 等字节显示成替换字符。现在按字节读取：先识别 UTF-16 BOM，再检查 NUL，再尝试严格 UTF-8，最后回退 GB18030；失败则提示并跳过。

3. **200 层列表撑破卡片**  
   每层 `1.55em` 缩进累积到 6101 px。现在超过 8 层的列表使用 `deep-nest`，不再继续增加缩进，避免横向溢出。

4. **同名文档无法区分**  
   侧栏副标题从「MD 文档」改为实际文件名；书名相同时可以靠 `same-a.md` / `same-b.md` 区分。

5. **多文件能力不够显眼**  
   打开按钮增加「可多选 / 可拖入」提示，侧栏增加一行说明。

## 还需要提升的地方

### 1. 本地存储容量仍是硬边界（优先）

入口允许 8 MB，但 `localStorage` 通常只有约 5 MB，且序列化的是全部文档。超过容量时能读、能切换，但刷新后可能丢；当前只有一条 toast 提醒。建议：

- 把文档正文迁到 IndexedDB，`localStorage` 只放偏好和元数据；
- 或至少打开前预估容量，并在书架条目标记「本次会话内有效」。

### 2. 超大文档的搜索是同步的

搜索索引和首轮匹配都在主线程。501 个标题约 155 ms，但如果文档有数万段落，打开搜索会有可感知卡顿。建议：

- 搜索输入 debounce；
- 索引构建移到 `requestIdleCallback` 或 Web Worker；
- 结果增量渲染。

### 3. 每份文档的阅读位置没有记忆

切走再切回来会回到文章顶部。对多文档阅读来说，建议在内存里记住每份文档的 `scrollTop`，切换时恢复；是否持久化到 `localStorage` 可另做选项。

### 4. 其他小边界

- 拖入文件夹时不会递归读取，只接收文件；可考虑 File System Access API。
- 文件选择打开时相对路径图片无法解析，远程图片不受影响。
- 畸形 frontmatter 的简单 `key: value` 解析可能得到奇怪标题，可增加 YAML 语法失败回退。
- 500 个标题的目录虽然可滚动，但可考虑折叠或虚拟列表。
- 多文件去重依赖「文件名 + 全文」，不是内容哈希；不同文件名但内容相同的文档会并存。
- 搜索只覆盖当前文档，不跨书架。

## 复现方式

测试脚本与夹具是临时文件，未放进项目；如需复跑，核心步骤是：

1. 在 `demo/` 启动静态服务器。
2. 用无头 Chromium / Edge 打开页面，开启 CDP。
3. 通过 `DOM.setFileInputFiles` 测真实多选；通过 `new File` + `DataTransfer` 测拖拽。
4. 通过 `Storage.prototype.setItem` 注入配额异常，通过 `Page.addScriptToEvaluateOnNewDocument` 禁用 `localStorage`。
5. 监控 `Runtime.exceptionThrown`、`window.onerror` 和 `unhandledrejection`。
